## 1. Жёсткие инварианты — нарушение означает откат правки

1. **Дисклеймер доз.** Каждый `doses[].note` обязан содержать education-only.
   Нельзя обходить `DOSE_DISCLAIMER` / `HAS_DISCLAIMER` / `doseNote()` в
   `app/data/compounds.js`. Merge-цепочка — единственный путь.
2. **Id препаратов.** Каждый `compounds[]` / `drugs[]` id должен существовать
   в множестве. Неизвестный id = провал аудита.
3. **Анимация.** Только `transform` и `opacity`. Никаких размытых анимированных
   блоков, вместо них — мягкий `radial-gradient`. Один тайловый паттерн на всё.
   Уважать `prefers-reduced-motion` и `data-motion="off"`.
4. **Текст не перекрывается.** Никаких фиксированных высот на текстовых контейнерах,
   никакого абсолютного текста поверх переменного контента. Мобайл — приоритет.
5. **PubMed не персистится.** Только in-memory `Map`, TTL 30 мин, максимум 24 записи,
   очередь 340 мс. Никакого localStorage, никакой БД.
6. **Диапазоны анализов универсальны.** Никакого ветвления по полу.
7. **`callout()` экранирует тело.** Никогда не передавать в него HTML.
8. **`render()` возвращает HTML-строку.** Никогда не возвращает `{redirect}`.

Плюс: **одна анимация на элемент**. Вход → удержание → выход — это один
keyframe-блок, а не два. Две `animation` на одном селекторе запрещены.

## 2. Стек и стиль

- Vanilla ES-модули. **Никакого npm, бандлера, TypeScript, фреймворка.** Это решение,
  а не недоделка.
- Никаких внешних зависимостей и CDN. Графики — SVG руками.
- CSS только через переменные: `--bg..--bg-3`, `--line`, `--text..--text-3`,
  `--accent*`, `--good/--ok/--warn/--bad/--critical`, `--radius*`, `--pad`, `--gap`,
  `--tap`, `--shadow-1..3`. **Переменной `--danger` не существует.**
- Текст интерфейса — английский. Комментарии в коде — короткие, по делу, английский.
- Брейкпоинты: 900 / 1000 / 1180 px. Мобайл = нижняя навигация + drawer.
- Store-ключ `neurodiff.state.v2`, версия схемы в `store.v`.
- Вьюха экспортирует `{ render(ctx), mount(root, ctx) }` либо именованные экспорты,
  которые обрабатывает `main.js`.
- Хелперы не дублировать: если что-то похоже на существующее в `core.js` — использовать его.
- Любой пользовательский текст в HTML идёт через `esc()`. Это не обсуждается.

## 3. Порядок работ — не перескакивать

Идёшь строго по фазам `PLAN-v4.md`: **Ф0 → Ф1 → Ф2 → Ф3 → Ф4 → Ф5 → Ф6**.

- Одна фаза = один законченный набор правок = один коммит.
- Внутри Ф3 (препараты) работаешь партиями по 20 записей. После каждой партии
  запускаешь аудит. Аудит не 12/12 — правку откатываешь, а не «починим позже».
- Перед переходом к следующей фазе — короткий отчёт (формат в п.5) и ожидание «да».
- Если задача из плана противоречит инвариантам — **инвариант главнее плана**.
  Останавливаешься и говоришь об этом.

## 6. Проверка перед каждым коммитом

Прогони мысленно (или скриптом) этот список и приложи результат в отчёт:

1. `#/dev/audit` — 12/12.
2. `grep -c "#" app/styles.css` вне `:root` — хардкод-цветов нет.
3. `grep -E "animation[^;]*(width|background-position|filter|box-shadow)" app/*.css` — 0.
4. `grep -rn "TODO\|FIXME\|lorem\|placeholder" app/` — 0.
5. `grep -rniE "sk-|bearer |password|api_key" app/ *.html` — ничего.
6. Браузер: 320px и 1440px, ни одного горизонтального скролла, текст не перекрыт.
7. `sw.js` `VERSION` поднят, если менялись ассеты.

9. Все новые `pubmed`/`refs` — реальные (PMID проверен, а не придуман).

## 7. Чего делать нельзя ни при каких условиях

- Выдумывать PMID, DOI, названия статей.
- Ставить дозы без дисклеймера или «рекомендовать» препараты.
- Добавлять ветвление диапазонов анализов по полу.
- Класть результаты PubMed в localStorage/IndexedDB.
- Коммитить ключи, токены, пароли. Репозиторий публичный.
- Ломать существующие URL-роуты: `#/compounds/:id` и остальные должны продолжать
  работать, старые хэши не терять.
- Делать две анимации на один элемент.
- Менять дизайн нижней навигации (5 пунктов, не больше).
